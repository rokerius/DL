В этом разделе вы познакомитесь с нейросетями для работы с данными, имеющими вид последовательностей некоторых токенов. Одним из самых богатых источников таких данных является NLP. Поэтому этот конспект и в этом блоке.

Для работы с такими данными есть несколько возможных режимов:

1. **Many-to-one**. На вход подается последовательность объектов, на выходе один объект. Пример 2: классификация текстов или видео. Пример 2: тематическая классификация. По предложению нефиксированной длины генерируем вектор вероятностей упоминания заранее фиксированных тем во входном предложении. Размерность выходного вектора постоянна и равна количеству тем.
2. **One-to-many**. На вход подается один объект, на выходе последовательность объектов. Пример: генерация заголовка к изображению (image captioning).
3. **Many-to-many**. На входе и выходе последовательности нефиксированной длины. Примеры: машинный перевод, суммаризация текста, генерация заголовка к статье.
4. **Синхронизированный вариант many-to-many**. На входе и выходе последовательности одинаковой длины, токены входной явно сопоставлены соответствующим токенам выходной. Пример: генерация покадровых субтитров к видео, PoS-tagging (part of speech tagging, для каждого слова в предложении предсказываем, что это за часть речи).

Чтобы хранить информацию о предыдущих токенах, мы вводим понятие внутренней памяти или **скрытого состояния** (**hidden state**, векторы $h_n$​). В простейшем случае оно выражается одним вектором фиксированной размерности. На каждом (дискретном) шаге в сеть подаются данные (например, эмбеддинг токена), при этом происходит обновление скрытого состояния. Пример: $h_n = \tanh\left(h_{n-1}W_1 + x_nW_2\right)$, а выходной: $y_n = h_n W_3$

Нетрудно представить себе и нейросеть с несколькими рекуррентными слоями: первый слой RNN будет принимать на вход исходную последовательность, вторая RNN — выходы первой сети, третья — выходы второй и т.д. Такие сети называют глубокими рекуррентными сетями.
![recurrent|551](https://yastatic.net/s3/education-portal/media/recurrent_many_layers_a91371b370_b5fae618d9_210eb6cabb.svg)

**Parameter sharing** — одни и те же веса модели используются многократно в разных местах.  
В RNN это значит: один и тот же набор матриц применяется на каждом временном шаге, поэтому модель умеет обрабатывать последовательности любой длины и не заводит отдельные параметры для каждого шага.

**BPTT — Backpropagation Through Time** — способ обучать RNN.  
Идея: “разворачиваем” RNN по времени как длинную нейросеть, считаем ошибку на выходах и прогоняем backprop назад через все временные шаги.

### Взрыв и затухание градиента в RNN

В RNN скрытое состояние на шаге $i$ вычисляется как $h_i = \tanh(h_{i-1} W_1 + x_i W_2)$
Функция потерь для $n$-го выхода имеет вид $L_n = L(y_n, \hat{y}_n)$
При этом $y_n$ зависит от $h_n$, а $h_n$ зависит от всех предыдущих скрытых состояний $h_i$, где $i < n$. При обратном распространении ошибки через время градиент проходит через цепочку скрытых состояний: $h_n \rightarrow h_{n-1} \rightarrow \dots \rightarrow h_1$

На каждом таком шаге градиент умножается на матрицу $W_1^T$ и на производную функции активации: $\nabla_{h_{i-1}} L = (\nabla_{h_i} L) W_1^T \odot \tanh'(h_{i-1} W_1 + x_i W_2)$

Поэтому при вычислении $\nabla_{W_1} L_n$ градиент много раз умножается на $W_1^T$. Примерно это можно представить так: $\nabla L \sim (W_1^T)^{n-1}$

Если у матрицы $W_1^T$ есть собственные значения, модуль которых больше $1$, то при многократном умножении градиент может быстро расти. Если же собственные значения по модулю меньше $1$, то градиент может быстро уменьшаться и стремиться к нулю.

Одно из простых инженерных решений - **gradient clipping**. Однако он не решает полностью проблему затухания градиента. Для борьбы с долговременными зависимостями чаще используют модифицированные RNN-архитектуры, например **LSTM** и GRU.

**Почему tanh?** Иначе все сломается, мы хотим выбрать ограниченную функцию, чтобы на каждом шаге не увеличивать состояние, сильно меняя распределение данных (поэтому не ReLU). Хотим одинаковую шкалу на всю модель, не хотим добавлять batch norm.

### Attention

**Механизм внимания** (**attention**) реализует эту интуицию путем предоставления декодеру информации обо всех токенах исходного предложения на каждом шаге генерации. Рассмотрим классическую модель внимания, предложенную Bahdanau et al. в 2014 году.

Обозначим скрытые состояния энкодера как $h=(h_0,h_1,\ldots,h_n)$, а скрытые состояния декодера как $s=(s_0,s_1,\ldots,s_m)$. Важно отметить, что $s_0=h_n$, то есть начальное скрытое состояние декодера задаётся последним скрытым состоянием энкодера, которое можно рассматривать как контекстный вектор.

На каждом шаге декодера $i$ будем вычислять attention scores. Для этого скрытое состояние декодера $s_i$ сравнивается с каждым скрытым состоянием энкодера $h_j$, где $j=0,\ldots,n$. В результате получаем вектор оценок $e_i$:

$e_i=[\langle s_i,h_0\rangle,\langle s_i,h_1\rangle,\ldots,\langle s_i,h_n\rangle]=[s_i h_0^T,s_i h_1^T,\ldots,s_i h_n^T]$
$\alpha_i=\mathrm{softmax}(e_i)$

Вектор $\alpha_i$ содержит веса внимания, показывающие, насколько сильно декодер на шаге $i$ должен учитывать каждое скрытое состояние энкодера.
Далее используем $\alpha_i$ для нахождения окончательного attention-вектора $a_i$:
$a_i=\sum_{j=0}^{n}\alpha_{ij}h_j$
Таким образом, $a_i$ является взвешенной суммой скрытых состояний энкодера. Чем больше вес $\alpha_{ij}$, тем больший вклад скрытое состояние $h_j$ вносит в итоговый attention-вектор.

Теперь на каждом шаге декодера $i$ вместо одного скрытого состояния $s_i$ будем использовать объединённый вектор $[s_i,a_i]$, то есть конкатенацию скрытого состояния декодера и соответствующего attention-вектора. Таким образом, декодер получает информацию о текущем состоянии генерации и одновременно учитывает наиболее важные части входной последовательности.
