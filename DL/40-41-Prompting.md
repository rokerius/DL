**Prompting** — это способ управлять поведением языковой модели с помощью текста, который передаётся ей на вход.

## In-context learning

ICL — способность модели осваивать задачу непосредственно из информации и примеров, находящихся в текущем контексте.

Допустим, модель не получила формального определения некоторой искусственной классификации:
```
Определи класс слова.
молоток → инструмент
яблоко → еда
отвёртка → инструмент
груша → еда
банан →
```
На основании примеров модель выводит правило и отвечает:
```
еда
```
Она как будто «научилась» задаче, но только внутри данного промпта. После завершения контекста эта новая классификация обычно не становится постоянным знанием модели.


**Zero-shot** означает, что модель получает инструкцию, но не получает примеров.
**One-shot** содержит один пример.
**Few-shot prompting** содержит несколько демонстраций.

**Reasoning prompts** — промпты, побуждающие модель выполнять промежуточные рассуждения, декомпозировать задачу, проверять условия или строить план решения.
```
1. Определи требования.
2. Выдели ограничения.
3. Рассмотри возможные решения.
4. Сравни решения.
5. Сформулируй итог.
```
**Chain-of-Thought** — цепочка промежуточных рассуждений модели, связывающая условие задачи с итоговым ответом. Есть zero-shot (без примеров) и few-shot с примерами. 

## Ограничения промптового подхода

- **Хрупкость формулировок**. Небольшое изменение промпта иногда сильно меняет результат
- **Ограниченное контекстное окно**. Модель может обработать только ограниченный объём текста.
- **Потеря в середине**. Модели нередко лучше замечают информацию в начале и конце контекста, чем в его середине. Поэтому критически важные ограничения не стоит прятать внутри длинного документа.
- **Галлюцинации**
- **Prompt injection**
- **Невозможность создать отсутствующее знание**

## Catastrophic forgetting

До сих пор мы обсуждали, как лучше сдвинуть модель к новой задаче. Но если смотреть на обучение как на последовательность адаптаций, быстро возникает неприятный эффект: улучшая одно поведение, мы можем разрушить другое.

![[Pasted image 20260610120552.png]]
*Если новая задача сильно меняет оптимальную границу принятия решений, а модель обучается только на новой цели, старая структура признакового пространства и старая decision boundary легко разрушаются.*

Теперь становится видно, что **PEFT** полезен не только из-за вычислительной экономии. Он ещё и ограничивает пространство изменений. Если базовые веса заморожены, то значительная часть старых знаний буквально не может быть стёрта. Новая задача реализуется через маленькую поправку, а не через глобальное переписывание сети.

Если всё-таки нужно обучать общие параметры и мы не хотим потерять старую задачу, появляется идея регуляризовать движение в важных для старой задачи направлениях. Один из самых известных подходов — **Elastic Weight Consolidation.**

Пусть  $F_i$ —  диагональный элемент Fisher information для параметра $\theta_i$ , измеряющий, насколько старая задача чувствительна к его изменению. Тогда objective новой задачи можно модифицировать так:
- $\mathcal{L}_{\mathrm{EWC}}(\theta)=\mathcal{L}_{B}(\theta)+\frac{\lambda}{2}\sum_i F_i(\theta_i-\theta_{A,i}^{*})^2$
Эта формула говорит: двигай параметры под новую задачу, но за изменение важных для старой задачи координат плати дороже.
