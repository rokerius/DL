Расскажу о деталях:
- Можно подгонять веса модели не только для последнего слова, но и для всех предыдущих. В итоге не одна фраза для обучения, а множество
- Модель не должна при обучении видеть будущие слова в тексте, для этого в матрице, что выше, мы ~~занулим~~ до softmax поставим им значение $-\infty$, для всех чисел, что ниже диагонали (нам нужно, чтобы столбцы остались нормализованными).
- Размер Attention Pattern равен квадрату размера контекста (bottle neck)
- Обучение можно распараллелить

Value условно связаны с Key. Чтобы обновить эмбеддинг для слова, мы складываем все значения value в столбец, получаем некое изменение и затем прибавляем к исходному эмбеддингу. Это и называется одной head of attention.

![](../attachments/%D0%A1%D0%BD%D0%B8%D0%BC%D0%BE%D0%BA%20%D1%8D%D0%BA%D1%80%D0%B0%D0%BD%D0%B0%202026-06-06%20%D0%B2%2021.14.46.png)

Есть три матрицы: Query, Key, Value с настраиваемыми параметрами. Параметров много, можем их сократить для Value, воспользовавшись скелетным разложением

Кратко и формально:
- $W_E$ - матрица эмбеддингов,
- $Q=XW_Q,\ K=XW_K,\ V=XW_V$ 
- $S=\frac{QK^{\top}}{\sqrt{d_k}},\ A=\operatorname{softmax}(S),$ 
- $\operatorname{Attention}(Q,K,V)=AV=\operatorname{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V,$

Таких слоев мы используем много и получается **Multi-head attention**, где для каждого head свои три матрицы W:

<img src="../attachments/%D0%A1%D0%BD%D0%B8%D0%BC%D0%BE%D0%BA%20%D1%8D%D0%BA%D1%80%D0%B0%D0%BD%D0%B0%202026-06-06%20%D0%B2%2021.28.03.png" width="335"><img src="../attachments/%D0%A1%D0%BD%D0%B8%D0%BC%D0%BE%D0%BA%20%D1%8D%D0%BA%D1%80%D0%B0%D0%BD%D0%B0%202026-06-06%20%D0%B2%2021.34.51.png" width="335">

$\substack{\text{Original}\\{embedding}}\quad \boxed{\vec{E}_i}+\Delta\vec{E}_i^{(1)}+\Delta\vec{E}_i^{(2)}+\Delta\vec{E}_i^{(3)}+\Delta\vec{E}_i^{(4)}+\cdots$

Так мы даем модели возможность узнать лучше как контекст может поменять смысл слов.
Помните я упоминал скелетное разложение матрицы Value? Отказываемся от этой идеи, будем в некую output matrix запихивать левую часть разложения (Value Up), а когда мы ссылаемся на матрицу Value для отдельной head of attention, будем иметь ввиду правую часть (Value Down).

- **Attention (cross-attention)** — общий механизм, который позволяет модели определить, на какие элементы входных данных обратить больше внимания.  $Q = YW_Q,\quad K = XW_K,\quad V = XW_V$
- **Self-attention** — частный случай attention, где запросы, ключи и значения берутся из одной и той же последовательности. Этот пример и разобран выше
- **Masked attention** — это attention с маской, которая запрещает модели учитывать некоторые токены. Чаще всего имеется в виду **causal mask** в языковых моделях: токен может смотреть только на себя и предыдущие токены, но не на будущие.

## Transformer
[3Blue1Brown](https://www.youtube.com/watch?v=wjZofJX0v4M&list=PLZHQObOWTQDM4E-dwvbnQTiyKDO-y9T2t&index=4)
[Умная статья](https://transformer-circuits.pub/2021/framework/index.html)

**GPT** = Generative Pre-trained Transformer
**Задачи**: voice-to-text, text-to-voice, text-to-text, text-to-image
- *Задача генерации продолжения текста - предсказание распределения вероятностей следующих слов*

High-Level Architecture:

![](../attachments/Pasted%20image%2020260606215056.png)


Данные многократно перемещаются между блоками Attention и MLP, в итоге в последнем векторе получим распределение вероятностей.

Обрати внимание на **residual connections**, они улучшают протекание градиента и сохраняем полезную часть старого предсказания.

<img src="../attachments/Pasted%20image%2020260608212901.png" width="299"><img src="../attachments/Pasted%20image%2020260608213007.png" width="395">

**Layer Normalization** нормализует значения признаков внутри одного объекта — например, внутри одного токена.
- $\operatorname{LayerNorm}(x)=\gamma\odot\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta$

**Positional encoding** — это способ сообщить Transformer’у порядок элементов в последовательности. 
- Синусоидальный encoding — позиции задаются через функции `sin` и `cos`; не требует обучения.
- Обучаемый encoding — для каждой позиции модель учит отдельный вектор.
- Относительный encoding — кодирует не абсолютную позицию токена, а расстояние между токенами.
- Современные варианты: RoPE и ALiBi

### Walkthrough
Представим, что нам нужно предсказать следующий токен в фразе. Тогда вся цепочка выглядит так:

1. **Сырая строка** сначала интерпретируется как Unicode.
2. **UTF-8 / базовое представление** переводит символы в байты или code points — в зависимости от типа токенизатора.
3. **Pretokenization** разрезает строку на более мелкие сегменты: слова, числа, пунктуацию, пробелы.
4. **BPE / WordPiece-подобный алгоритм** применяет выученные слияния и получает конечную последовательность токенов из словаря .
5. **Токены превращаются в индексы**, затем индексы — в эмбеддинги токенов через матрицу .
6. **Добавляется позиционная информация** — либо явным сложением с позиционным вектором, либо через механизм вроде RoPE.
7. **Стек блоков трансформера** многократно повторяет два действия: attention-маршрутизацию по контексту и FFN-переработку признаков внутри каждой позиции.
8. **Последний скрытый вектор** на нужной позиции проецируется в пространство словаря линейной головой.
9. **Softmax** превращает логиты в вероятности по токенам.
10. **Выбранный следующий токен** добавляется к префиксу, и цикл повторяется; на инференсе для ускорения при этом используют KV-cache.
